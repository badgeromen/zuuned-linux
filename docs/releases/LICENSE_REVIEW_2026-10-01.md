Recommended release approach: GPL-3.0-or-later for original app code, subject to
owner approval and resolution of third-party rights. This permits redistribution,
modification and commercial use under its terms; it does not prohibit forks.
A permissive license on original files alone cannot remove the GPL distribution
obligations introduced by the currently linked components.

Supply complete corresponding source (app, actual libzune, covered dependencies,
patches and build/install scripts) through a compliant download arrangement.
A GitHub autogenerated source archive alone omits the submodule's contents and
is not the complete source for this bundle. Debian copyright files are useful
notices, but do not themselves provide the complete source. Adding a LICENSE
file alone will not make the current artifact publication-ready; rebuild with
approved notices/font changes as needed and revalidate that exact artifact.

### Confirmed for the current executable

- ELF `NEEDED` entries directly name `libmpv.so.2`, `libavformat.so.61` and
  `libavcodec.so.61`. This is linking, not merely launching an unrelated tool.
- The bundled Debian `libmpv2/copyright` explicitly identifies its binaries as
  GPL-3+ because of libsmbclient. Upstream's optional LGPL configuration does
  not describe this shipped library.
- FFmpeg's license depends on its build; the GPL components in this Debian
  package must be accounted for. Merely describing FFmpeg as LGPL is inadequate.
- A downloads-only Git repository can coexist with GPL compliance. Under
  GPLv3 section 6(d), equivalent access to matching Corresponding Source can
  be supplied on another server, with clear directions next to the binary.
  Keep it available as required; a generic upstream home page or inaccessible
  private Git server is not a matching-source delivery plan. The current
  uncommitted font changes and pinned libzune must be included in source for
  this particular binary, along with required dependency source/build material.
- If the owner intends to keep the whole application's source private from
  recipients, this exact linked build is not a suitable distribution candidate.
  Investigating an LGPL-compatible dependency build would be separate work,
  would still leave library source/notice/relink obligations, and would require
  rebuilding and testing. It is not a switch that clears the current binary.

### Notice completeness finding

The actual AppDir has no `usr/share/common-licenses` directory, while bundled
Debian copyright files reference files there (including GPL-2 and GPL-3).
The copied notices archive therefore does not by itself supply all the license
texts referenced by those notices. Add the applicable texts and retain the
original per-package notices. Include Permanent Marker's Apache-2.0 license
and Font Diner attribution, and the chosen Specimen Alien terms.

An inventory of the exact packaged copyright files, their declared license
expressions and referenced common license files is retained as
`evidence/license-notice-inventory.json` beside the candidate. Package-level
copyright files can cover source/build tools that are not shipped; this index
is evidence, not a legal conclusion for every compiled file.
